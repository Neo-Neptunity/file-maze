# ファイル迷路 開発用のテスト

MOD 本体は `file-maze/mod/`。配る zip に入れたくないので、テストは本体に置かず、ここにまとめる。
`unit.mjs` は `node` だけで動く。`browser.mjs` は、Edge（なければ Chrome）が入っていれば動く。MOD のファイルは、`unit.mjs` では一時フォルダへコピーして読む（`stage.mjs`）。

| ファイル | 内容 | 使い方 |
|---|---|---|
| `unit.mjs` | 画面を持たない部品の試験：乱数・階層（隠しフォルダと node_modules は数えない）・道すじのフォルダ・スタートとゴールの組み・壁に刻む名前・**迷路の生成（全部の升に行ける・輪がない・同じ種なら同じ・分かれ道の多さの段階）・スタートとゴール（道は最短・ゴールはいちばん遠い）・区域の割りふり（道を進むと順に進む・枝は付け根の区域）・座標と壁・道すじを実際に歩ける・壁は通れない・壁の板（閉じた壁がすべて 1 枚の板に入る）**・報酬と買い物・壊れた記録の修復・manifest の決まり・ファイルを変える／読む／通信する呼び出しがないこと・画面の文章に括弧の注釈がないこと | `node file-maze/dev/unit.mjs` |
| `browser.mjs` | 本物の `index.js` を、ヘッドレスの Edge で動かす（偽の explorerPlus を渡す）。画面を PNG に撮る。ボットが本物の物理で歩く | `node file-maze/dev/browser.mjs [出力フォルダ] [--scenario=…] [--seeds=3] [--w=1280 --h=720] [--dpr=2]` |
| `fake-tree.mjs` | 試験用の偽のフォルダの木（日本語と英語の名前・深い枝・9 個のフォルダ・空のフォルダ・隠しフォルダ・node_modules） | |

## browser.mjs のシナリオ
- `look`：はじめの画面 → 出発前 → 遊んでいる画面 → **迷路の全体（正解の道すじを金色で重ねた 1 枚）** → 区域が変わる所 → 手がかり。見た目を調整するときに使う
- `gen`：大きさ 3 種 × 分かれ道 3 種の迷路を作って、始まるまでの時間（3 秒以内）・道のり・壁の板の数・絵の大きさを見る。`--dpr=2` で高解像度の画面
- `solve`：ボットが、スタートからゴールまで、正解の道すじを本物の `stepMove` で歩く。**歩くあいだ、上の道すじの表示が、フォルダの順に変わること**も確かめる（階層が連続して見える作りの確認）
- `flow`：画面のつながり（出発前の選択・手がかり・中断・つづける・マウスの押しっぱなし・クリア・コインとスタンプ・ショップ・図鑑・記録の保存・あきらめる）。出発前の文章に「部屋」「扉」が出ないことも見る

## 数字を変えるとき
- 迷路の大きさは `maze.js` の `SIZES`、分かれ道の多さは `BRANCH`（「いちばん新しい升から続ける」割合）。測定：31×19 で 1.0 は行き止まり 10%・道のり 317、0.8 は 23%・152、0.5 は 31%・95。0.6 より小さくしても行き止まりの割合は頭打ち（約 30%）
- 通路と壁の太さは `maze.js` の `CELL`（通路 38）・`WALL`（壁 24。ここに名前を刻むので、文字の大きさ 16px とあわせて決めている）・`HALF`（プレイヤーの四角の半分 8）
- コインの式は `rewards.js` の `coinsFor`（長さ `len` に比例）

## 確かめられないこと
- 本物の explorer_plus の中での動き。偽の本体で代用している。クイックアクセスの中身・巨大なフォルダの `getTree` の重さ・キーが MOD の画面へ届くか
- 手触り（歩く速さ・通路の広さ・迷路の大きさの感じ）。ヘッドレスは、ソフトウェア描画なので、1 コマの速さも本物とはちがう
- 文字の形はそのPCのフォント（游ゴシック・メイリオ）で決まる。壁は文字の形に関係なく通れる・通れないが決まる（文字は飾り）ので、PC がちがっても迷路は壊れない
